{{ if $zh }}难点不在扩展本身，而在跨版本、系统与架构的可靠分发。{{ else }}The hard part is not the extension—it is reliable delivery across versions, systems, and architectures.{{ end }}

{{ if $zh }}没有 pig 的时候{{ else }}WITHOUT PIG{{ end }}

{{ if $zh }}每一层都要手工处理{{ else }}Manual at Every Layer{{ end }}

  • {{ if $zh }}寻找正确的仓库、包名或源码{{ else }}Find the right repository, package, or source{{ end }}
  • {{ if $zh }}逐一匹配 PG 大版本、系统与架构{{ else }}Match the PG major, OS release, and architecture{{ end }}
  • {{ if $zh }}没有二进制包时自行准备工具链与构建流程{{ else }}Own the toolchain and build when no binary exists{{ end }}
  • {{ if $zh }}换主机或升级大版本后重新执行{{ else }}Repeat the process for every host and major upgrade{{ end }}

{{ if $zh }}用 pig 之后{{ else }}WITH PIG{{ end }}

{{ if $zh }}一套一致的工作流{{ else }}One Consistent Workflow{{ end }}

  • {{ if $zh }}repo set 生成按地域选择的 apt / dnf 配置{{ else }}repo set writes region-aware apt / dnf configuration{{ end }}
  • {{ if $zh }}install 解析名称、PG 版本、系统与架构{{ else }}install resolves names, PG majors, systems, and architectures{{ end }}
  • {{ if $zh }}build 为缺包目标提供基于规格的构建路径{{ else }}build provides a spec-driven path when no package exists{{ end }}
  • {{ if $zh }}最终仍是原生 RPM / DEB，不引入数据库运行时依赖{{ else }}The result stays native RPM / DEB, with no database runtime dependency{{ end }}

{{ if $zh }}PIG 始终是可选工具：Pigsty 仓库 可直接由 apt / dnf 使用，也不会成为数据库运行时依赖。{{ else }}PIG remains optional: the Pigsty repositories work with plain apt and dnf, and PIG never becomes a database runtime dependency.{{ end }}
